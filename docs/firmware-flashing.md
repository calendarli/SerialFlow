# 固件烧录

在底部「发送消息 / 发送文件」旁打开「固件烧录」。

| 目标       | 烧录方式                        | 固件           |
| ---------- | ------------------------------- | -------------- |
| STM32      | UART（芯片内置系统 Bootloader） | Intel HEX、BIN |
| STM32      | Ymodem（设备自带 Bootloader）   | 单个 BIN       |
| STM32      | ST-LINK / SWD                   | Intel HEX、BIN |
| ESP32 系列 | UART 下载模式                   | 一个或多个 BIN |

## 工具准备

- ESP32：安装时尝试获取官方 esptool 5.3.1 独立工具，按系统和架构打包，无需安装 Python；下载失败时可手动指定工具。
- STM32 UART（芯片内置）和 ST-LINK / SWD：先安装 [STM32CubeProgrammer](https://www.st.com/en/development-tools/stm32cubeprog.html)。自动检测标准安装目录；未找到时，在高级设置中选择安装目录里的 `bin/STM32_Programmer_CLI.exe`。不要只复制一个 EXE，其运行依赖完整安装目录。
- STM32 Ymodem：目标设备必须已有支持 Ymodem CRC16 的自带 Bootloader，并能进入接收状态。此方式由 SerialFlow 直接控制串口，不调用 STM32CubeProgrammer；芯片内置系统 Bootloader 不使用 Ymodem。
- UART（芯片内置）、ST-LINK / SWD 和 ESP32 的高级设置可指定工具位置、查看版本、重新检测。esptool 自定义路径要求 5.x 原生可执行文件。
- 支持准备 macOS x64/arm64、Linux x64/arm64/armv7 以及 Windows x64 的 esptool。其他架构可指定兼容的原生工具；macOS/Linux 尚未完成硬件验证。

## 烧录步骤

1. 选择芯片系列和烧录方式；刷新并选择串口或 ST-LINK。无需预先在调试区打开串口。
2. 选择固件。文件窗口默认打开上一次成功选择固件的目录，关闭并重开应用后仍会记住；取消选择不会改变记录。STM32 UART（芯片内置）和 ST-LINK / SWD 支持 HEX、BIN：HEX 使用文件内地址，BIN 必须指定起始地址，默认 `0x08000000`，有 Bootloader 的工程需要按实际布局修改。STM32 Ymodem 只选择单个 BIN，界面不填写写入地址，地址由设备 Bootloader 决定。
3. ESP32 根据工程输出添加「文件 + 地址」。合并 BIN 的起始偏移也必须按生成配置填写；不统一猜测 bootloader、分区表或应用地址。可显式选择 ESP32 型号，也可自动识别。
4. STM32 UART（芯片内置）、ST-LINK / SWD 和 ESP32 可先「检测芯片」，详情查看日志。检测不擦写固件，但连接/复位会影响正在运行的程序。Ymodem 不提供通用芯片检测命令。
5. 普通方式点击「开始烧录」后检查工具和文件、连接设备并按工具流程写入。STM32 UART（芯片内置）和 ST-LINK / SWD 可选烧录后校验；ESP32 保留工具默认写入校验。Ymodem 点击「开始烧录」后由 SerialFlow 与接收端双向握手并传输，设备负责擦除、Flash 写入和最终校验。
6. 底部状态条显示当前阶段、进度和耗时。Ymodem 还显示已获接收端确认的字节数与文件总大小；任务完成后仍保留百分比和进度条。必要时可导出最近 400 行日志。

STM32 UART 需按具体型号手册配置 BOOT 并复位进入系统 Bootloader。烧录后恢复正常启动配置并手动复位；UART 不支持 SWD 的软件复位命令。ST-LINK 的「复位下连接」还需要 NRST 接线。

ESP32 有自动下载电路时通过 DTR/RTS 进入下载模式；否则选择「手动进入下载模式」，按开发板的 BOOT/RESET 操作。手动模式不会自动生成所有开发板通用的复位时序。

### STM32 Ymodem 流程

先按目标设备的说明让自带 Bootloader 进入 Ymodem 接收状态，再选择「Ymodem（设备升级）」、BIN 文件、串口和波特率。串口使用 8 数据位、无校验、1 停止位。设备若需要自定义的进入升级命令，应在开始传输前由设备自身流程完成；此通用模式不发送该命令。

如果设备 Bootloader 在多个串口同时发送 `0x43`，并通过主机回传 `0x43` 选定升级串口，可勾选「监听 C 选口握手」。勾选后 SerialFlow 立即独占所选串口，持续监听，每收到一个 `0x43` 就回传一个 `0x43`；界面显示「已收到并回复」后，选择 BIN 并点击「开始烧录」。监听与烧录共用同一个串口连接，烧录从 Ymodem 文件信息包开始，不再等待第二个初始 `C`。取消勾选会停止监听并释放串口；没有收到 `0x43` 前不能开始烧录。该回传是本设备的**选口扩展握手**，不是标准 Ymodem 的一个额外数据包；未勾选时仍按标准流程，点击「开始烧录」后等待接收端的首个 `C`。设备必须在收到选口回复后准备接收 Ymodem 文件信息包。

#### 通讯包和控制字节

- `C = 0x43`：接收端请求使用 CRC16 或继续发送下一阶段；`ACK = 0x06`：接收端确认；`NAK = 0x15`：请求重发；连续两个 `CAN = 0x18 0x18`：取消；`EOT = 0x04`：文件数据结束。
- 信息包和结束空包使用 `SOH = 0x01`、128 字节负载；数据包使用 `STX = 0x02`、1024 字节负载，剩余不足 1024 字节时改用 128 字节包。包结构为「包头、1 字节序号、序号按位取反、固定长度负载、2 字节 CRC16 高位在前」。序号从数据包 `1` 开始并按 8 位回绕，信息包和结束空包的序号都是 `0`。
- CRC 采用 CRC-16/XMODEM：多项式 `0x1021`、初值 `0x0000`，对固定长度负载计算。信息包负载为 `文件名\0十进制文件大小\0`，其余字节补 `0x00`；数据尾包补 `0x1A`；结束空包的负载全为 `0x00`。

#### 双端握手与完成条件

| 阶段     | SerialFlow 发送 / 等待                             | 接收端必须回应                                                       | 超时或拒绝时的处理                                                                  |
| -------- | -------------------------------------------------- | -------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| 启动     | 最多等待 30 秒；接收端此前的提示文本不作为协议回应 | `C`                                                                  | 未收到 `C` 则失败，不发送文件                                                       |
| 文件信息 | 发送 128 字节信息包 `#0`                           | 先 `ACK`，再于 60 秒内发 `C`                                         | `NAK`、重发请求 `C` 或等待 `ACK` 超时会重发同一包；已收到 `ACK` 后等不到 `C` 则失败 |
| 文件数据 | 依次发送数据包 `#1` 起；每包确认后才推进进度       | 每包 `ACK`                                                           | `NAK`、重发请求 `C` 或等待 `ACK` 超时会重发**同一序号**的包                         |
| 文件结束 | 发送 `EOT`                                         | 标准流程为 `NAK → EOT → ACK`；也接受直接 `ACK`，随后于 60 秒内发 `C` | `NAK` 时再次发送 `EOT`；等待确认超时可重发；确认后等不到 `C` 则失败                 |
| 会话结束 | 发送 128 字节全零结束空包 `#0`                     | `ACK`；本设备可在此前上报 `boot=<版本>;app=<版本>` 的 ASCII 文本     | 未确认则重发空包；只有收到该 `ACK` 才显示「Ymodem 传输完成」                        |

信息包、每个数据包、`EOT` 和结束空包各最多发送 **10 次（含首次）**；每次串口写入和等待确认的上限均为 30 秒。接收端连续两个 `CAN` 表示取消；单个 `CAN` 后未在 1 秒内收到第二个 `CAN` 属于无效取消序列。取消、异常控制字节、串口断开或重试耗尽都会使任务失败。用户停止或传输失败时，SerialFlow 会**尝试**发送两个 `CAN`，随后关闭专用串口并按设置恢复原有连接。它不会把未确认的包计为成功，也不会在失败后自动断点续传。

支持常见的 `EOT → NAK → EOT → ACK`，也兼容部分 STM32 IAP 接收端的 `EOT → ACK`。文件名字段使用 ASCII；本地文件名不能用 ASCII 表示或超过 64 字符时，发送名称 `firmware.bin`，文件内容不变。目标设备对文件名、大小、应用地址和 Flash 容量的接受规则仍须以其 Bootloader 为准。

「Ymodem 传输完成」表示接收端已确认全部数据和结束空包，**不代表 SerialFlow 已独立读取并校验 Flash**，也不证明设备已成功启动新固件。请以设备升级程序的最终结果和重新启动后的实际行为验收。

## 串口与任务行为

- 每次运行一个烧录/检测任务，切换页签不停止任务。
- 同一串口正在传输或配置接收文件时，烧录被拒绝，先停止传输/接收。
- 烧录前关闭本应用已有的目标串口，期间拒绝调试打开和写入；其他串口可继续使用。
- 「结束后恢复原串口连接」默认关闭，启用后恢复原来已打开连接的串口参数。自动发送与受影响的指令循环需要重新启动。
- 「停止」对工具烧录终止进程树；对 Ymodem 尝试发出取消序列并关闭串口。固件可能已部分擦写，需要重新完整烧录；没有回滚和断点续烧。
- 退出应用也会停止任务。过程中不要退出或断电。
- 「整片擦除」用于工具烧录，默认关闭且不持久化，选择后开始烧录前再次确认。它可能删除设备保存的用户数据。Ymodem 不显示此选项，擦除范围由设备 Bootloader 决定。

## 支持边界

普通 STM32 工具烧录的 HEX 验证记录长度、校验和、结束记录、扩展地址及地址重叠；BIN 验证地址和大小。ESP32 多文件烧录还检查文件间重叠。通过检查后生成临时快照供工具烧录，结束时清理。Ymodem 单独检查 BIN 路径、非空和最多 128 MB 的大小，读取文件后直接按协议发送；目标写入地址和可用容量由设备 Bootloader 检查。

普通 STM32 工具烧录只允许主 Flash 地址窗口内的数据，排除 RAM、选项字节等区域；实际芯片容量和写入支持由官方工具检查。Ymodem 不读取目标芯片信息，也不能替设备验证地址或容量。HEX/BIN 不一定包含可验证的目标芯片型号，文件结构检查不能证明它适用于当前硬件。ESP32 固件保留 esptool 的芯片、容量和安全检查，不传递 `--force` 等绕过参数。

首版不支持 ELF、ESP32 HEX、USB DFU、外部 Flash loader、解除保护、eFuse、配置安全启动或批量并行烧录。可在现有任务管理下增加后续适配器。

## 开发验证

```text
bun run build
bun test tests/firmware.test.ts
bun test tests/ymodem.test.ts
bun run test:ui
```

自动测试覆盖固件预检、参数生成、模拟任务成功/失败/取消、Ymodem 握手与重传、资源释放，以及真实 Electron 界面和 preload 接口。测试使用模拟接收端，不会擦写硬件。需要使用实际 STM32 和 ESP32 开发板补充烧录、启动、断线重烧与串口恢复验收。

内置工具来源、版本和校验和见 `resources/firmware/NOTICE.md`。可运行 `bun run fetch:esptool` 重新获取固定版本。
